# C25 — Controlled live and release-candidate qualification

Phase: P08. Status: planned. Required predecessor: C24.

## Outcome

Establish required real-service behavior against an explicitly designated acceptance scope.

## Inputs and dependency gates

C24; owner-approved expanded live-checks matrix, approved account/tenant/endpoint/resource/budget/cleanup manifest and pinned release-candidate inputs.

Read the [common execution contract](../IMPLEMENTATION-PLAN.md),
[review protocol](../review-protocol.md), and [test catalogue](../test-catalogue.md).
Concrete interfaces follow accepted G01 ADRs. Freeze all source/shared dependency
inputs; active neighboring worktrees and unavailable methods cannot count as pins.

## Milestones

1. Select least-privileged designated tenants/accounts and explicit reversible operations; separate reads, writes, inference, exams and MCP authority.
2. Run actual used SDK/Academy/Gateway/Harness contracts, positive/deny/unknown/recovery cases, and independent credential isolation.
3. Record sanitized request/trace IDs, exact inputs, outcomes, readback and cleanup; bound scan/inference/assessment consumption.
4. Complete parity ledger with source/fixture/native/live evidence separately; no unsupported/skipped operation is marked passed.

## Required acceptance

- Any changed UI also requires T09 actual native keyboard/focus/accessibility checks; global requirements are not deferred solely to C24.

- T21 plus feature-specific IDs: real scan, scoped admin round trips, streaming, learner authority and MCP approve/deny/refresh/revocation as applicable.
- Every required L01–L18 row in the approved [live matrix](../live-checks.md) passes against designated scope. Access gaps are blocked, not not-applicable; reductions require a recorded owner decision and revised review.
- Lost/uncertain write outcomes require operator-visible reconciliation and cleanup evidence, not assumed rollback.
- Freeze candidate source/dependencies/build flags; no production destructive tests or implicit live fallbacks.

G01/C01 must bind these assertions to exact commands and fixture/native targets
before execution. Run appropriate regressions when changes reach earlier chunks.
No test result, native acceptance, or live qualification is claimed by this file.

## Evidence and completion

Designated live scope, redacted per-workflow receipts, readback/cleanup ledger, blocked-gap report and cumulative review.

Use the [implementer prompt](../prompts/implement-chunk.md) and
[independent reviewer prompt](../prompts/review-chunk.md). Require ≥9/10 overall
and in architecture, behavior, authority/security, and validation; no required
fixes or absent mandatory evidence. Preserve attempts, raw verdicts, hashes, and
remediation. Commit only the reviewed tree; do not unlock the next chunk early.

## Safety and recovery

Stop on unexpected tenant/authority/cost or uncertain resource state. Missing mandatory access blocks stable release; do not change scope silently.
