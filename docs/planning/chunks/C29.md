# C29 — First-run wizard and add-tenant sheet

Phase: P09. Status: planned. Required predecessor: C28.

## Outcome

A first-run user is taken from welcome to a verified tenant with credentials in the vault, selected products, optional starter packs and optional Academy account; an existing user adds a tenant through the same component in add mode. Realises D013.

## Inputs and dependency gates

C28; screens/wizard.md. Read the [common execution contract](../IMPLEMENTATION-PLAN.md),
[review protocol](../review-protocol.md), and [test catalogue](../test-catalogue.md).
Read the [UI v2 specification](../../architecture/ui-v2/DESIGN-V2.md) and its
companions; the frozen prototype under `docs/architecture/ui-v2/prototype/` is
an immutable input. Freeze all source/shared dependency inputs.

## Milestones

1. Intents `verifyTenantSetup` (streaming `VerifyStep`, using existing reads per admitted product; unavailable products report "not available", never a result), `completeOnboarding`, `addTenant`; scan key required, management client and Gateway optional (D013, P17); secret entry only through the host secret sheet returning vault ids; v1 import offered as a secondary action on the tenant step.
2. Wizard component with steps, validation (`aria-invalid`, `aria-describedby`, invalidation signature), rail context line, finite "Open Prisma AIRS", add mode (sheet 1160×780, 244px rail, Cancel semantics).
3. Warnings from verify become Inbox items at completion (type defined here, rendered in C30).
4. Fixtures for every R2On* board and R2AddTenant; copy.ts for the wizard including the welcome and trust text.

## Required acceptance

- `onboarding` transitions needed → inProgress → done; cancel in add mode writes nothing: the draft and its credentials are discarded (P27; stronger than the leftover credential the prototype assumed).
- No intent persists, echoes or logs a secret: per P25 (accepted in C28) a secret enters once as `EnteredSecret` from the webview field and leaves it nowhere else; the host test on the mock runtime (`setup_draft_intents_cross_ipc_without_echoing_secrets_or_creating_tenants`) shows no receipt, snapshot or Keychain call carries it.
- Unavailable products (AIS, AES) are not selectable and never verified; V2-T19 for the products step.
- Live: verify against the designated read-only tenant (Vulture) under the owner scope, recorded as a redacted receipt; no writes.
- T09 for every step; V2-N02.

## Evidence and completion

As C28, plus the live verify receipt.

## Safety and recovery

Stop on any unexpected tenant or authority state. Missing live access blocks the live row; it does not pass.
