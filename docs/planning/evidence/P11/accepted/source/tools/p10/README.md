# C45 / P10 explicit future verification

P09 remains an immutable historical prerequisite. Its full source and originally
ignored evidence are archived under C45 activation; no old inventory or verdict
is edited. C30/C41 owner standing remains distinct from independent scores.

`seal.py` derives all current mapped native IDs plus C45's identity assertions
and the approved 16 selected repository commands. `c45_baseline` uses the existing
Rust Runner, Manifest and Environment; it retains raw RunRecords and excludes
setup already performed offline, duplicate frontend execution and the two real
login-Keychain/search-list probes. P10 selects C45 rather than replaying retired
C01-C44 commands. Production FileStore/authority and disposable-file Keychain
regressions replace old import/adoption and private-Keychain probes explicitly.

`supervise.py` requires guest Terminal ancestry, a global UI-writer flock, sealed
source, exact fixture/bundle bindings and foreground checks. Every stage keeps
raw stdout/stderr and the original runner/native records. It stops on failure
and preserves completed stages. Partial stages require explicit ownership and
raw-result diagnosis; model/tool exit does not terminate this Terminal-owned job.
`native.py` only relocates existing driver evidence paths and uses their original
assertions. `acceptance_c45.py --smoke` is a short current identity preflight,
never cumulative acceptance. The real C45 rows also require separate qualified
production-interface and mapped coverage; UI absence is not non-adoption proof.

`finalize.py` binds actual executions. `qualification.py` verifies complete ID
membership, approved command/cwd, original RunRecord/native results, input/log
hashes and per-driver evidence. Exact reuse requires executable, complete bundle,
relevant helper closure, flags and conditions. Changed test/lint targets must
execute. Unaffected carry retains original artifacts and requires actual unchanged
dependency-file proofs. No assertion retirement can be introduced by omission.
P10 consumes the same qualified candidate without claiming new execution.

`packet.py make|audit C45|P10 attempt-NN` uses a fresh read-only configured Codex
review through the retained launcher. Audits never assign scores. C45 can be
accepted at 8 under D034, then needs actual full9 before P10; P10 needs actual
full9 with empty fixes/blockers/gaps. C26/P08 remains open/manual fallback.

Both release-candidate packaging and the actual production build entrypoint
require C01-C25 plus genuine audited P09/P10 proof, including C45 full9 member and
qualified coverage. C26 is not a circular prerequisite of its own release build.
This work authorizes no live product calls, user credential/data discovery,
publication, signing, notarization or installation.
