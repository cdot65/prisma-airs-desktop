# Prisma AIRS Desktop v2 — 2.0.0

The first stable release of v2. It is for macOS on Apple silicon. It is
signed with the Developer ID of Calvin Remsburg (team G5QLZ5A8TA), and both
the app and the DMG are notarized by Apple with the ticket stapled, so they
pass Gatekeeper offline.

The exact bytes are recorded in `docs/planning/evidence/C26/`:
- `release-build.json`: the unsigned build and its source fingerprint;
- `release-signing.json`: hashes before signing, after signing and after
  stapling.

## Install

1. Open `Prisma AIRS Desktop v2_2.0.0_aarch64.dmg`.
2. Drag **Prisma AIRS Desktop v2** to Applications. An account without
   administrator rights can use `~/Applications` instead.
3. Open it. The first time, macOS asks whether to open an app downloaded
   from the internet: choose **Open**.

The app needs no developer tools, Node, Bun or other runtime. The Harness
engine ships inside the app, signed, and the app checks its hash before
starting it.

## Update and roll back

- **Update.** Quit the app, then replace it with the new version's app from
  its DMG. Your data stays in place.
- **Roll back.** Install the previous version (0.2.0) the same way. 2.0.0 and
  0.2.0 share the data format, so work saved in either opens in the other.

## v1 alongside v2

- v2 uses its own data folder and Keychain items. It never changes v1's
  folder (`~/Library/Application Support/Prisma AIRS Desktop`) or v1's
  Keychain items (`io.cdot.prisma-airs-desktop`).
- **Settings › Import from v1** copies reviewed v1 work into v2 and leaves
  v1 as it was.

## Reset and uninstall

- **Settings › Reset local data** removes v2's local data and its Keychain
  items, and returns the app to first launch.
- **To uninstall:** reset first (so the Keychain items go too), quit, and
  move the app to the Trash.

## Known limitations in 2.0.0

These come from the services and the SDK, as the controlled live
qualification (C25) found them:

- **DLP filtering profiles cannot be edited.** The live service stores
  `direction` as `c2s`/`s2c` and `log_severity` in lower case. The SDK's
  request contract (scm-sdk 0.2.4) accepts neither, so a save is refused
  before anything is sent. This is an SDK follow-up.
- **DLP data profiles.** The service answers HTTP 400 to reads and writes of
  a data profile by ID; the inventory still lists them.
- **Gateway workspace provisioning stops at the IAM binding.** IAM refuses
  `resource_type: workspace` bindings from the public API. The app keeps
  the scope and workspace it made, says so, and asks for reconciliation.
- **A cached Gateway answer fails.** A Gateway response cache replays an
  answer without `finish_reason`, which the SDK's stream contract refuses;
  the app reports an invalid response. This is an SDK follow-up.
- **Inactive AI security profiles.** The service does not list them, so a
  profile saved inactive does not read back. The app says so in the review
  before saving.
