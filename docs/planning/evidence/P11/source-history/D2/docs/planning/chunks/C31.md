# C31 — Reviews, Administration inventory, key rotation

Phase: P09. Status: planned. Required predecessor: C30.

## Outcome

Configuration reviews bind tenant, resource and typed name in the core; Administration renders from an inventory with per-tab capabilities; key rotation is a three-stage flow with one-time secret disclosure through the host.

## Inputs and dependency gates

C30; screens/reviews-administration.md. Read the [common execution contract](../IMPLEMENTATION-PLAN.md),
[review protocol](../review-protocol.md), and [test catalogue](../test-catalogue.md).
Read the [UI v2 specification](../../architecture/ui-v2/DESIGN-V2.md) and its
companions; the frozen prototype under `docs/architecture/ui-v2/prototype/` is
an immutable input. Freeze all source/shared dependency inputs.

## Milestones

1. Scopes `Review`, `AdminInventory` (every tab mapped to an admitted `ManagementResource`/`GatewayRead`/C13 read and every action to an admitted `ChangeKind`+`ChangeAction`; AIS and AES unavailable with their gate), topic inventory with distinct detector/topic key types; intents `openReview`, `confirmReview{typed}`, `acknowledgeDeployment`; key rotation is the admitted sequence `ApiKeys·Version` → local acknowledgement → `ApiKeys·Delete` with readback; the issued secret uses the existing `RevealSecret`/`ForgetSecret` host path, is never persisted, and is dropped on every review exit including tenant switch and context retirement.
2. Administration accordion and tables; review surface with diff, impact, typed name, applied panels; rotation panel states 1–4 (screens/reviews-administration.md); rotation reminder as a distinct Inbox item; two labelled timestamps (deployment acknowledged, old key removed) stored once; unknown outcomes shown as unconfirmed with reconciliation.
3. Playground verdicts profile-aware with detector and topic results independent; applied topic examples classify under the topic.
4. Fixtures for R2Admin and R2Review.
