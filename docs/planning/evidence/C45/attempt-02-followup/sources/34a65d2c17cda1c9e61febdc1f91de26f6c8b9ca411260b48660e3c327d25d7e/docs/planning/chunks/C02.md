# C02 — Rust context, protected credentials, and native SDK qualification

Phase: P01. Status: implemented, in review. Required predecessor: C01 (complete).

## Outcome

Give scan-only tenants a Rust-owned credential/context/request lifecycle and qualify the accepted SDK on macOS.

## Milestones

1. Implement explicit tenant configuration and scan-key onboarding; management/inference/MCP credentials remain separate capabilities.
2. Integrate one application-owned async runtime, bounded work/cancellation, context admission, and sanitized errors; renderer carries nonsecret projections and transient entered inputs only.
3. Implement Keychain/session-only credential adapters, reset/cleanup, and protected state identities without plaintext fallback.
4. Run accepted SDK subset and host adapter contracts on macOS ARM64; record actual source hash/toolchain/target, not Linux evidence as Mac proof.
5. Preserve explicit endpoint overrides: show the destination/capability changes for operator review, bind credentials to the approved HTTPS destinations, and invalidate prior context/reviews on change. No redirect or silent override can forward an old credential to an unapproved origin.
6. Support explicit reviewed import of nonsecret tenant-profile metadata (labels, region/TSG identifiers, approved endpoint configuration). Whitelist metadata fields, ignore/discard embedded secrets, do not follow referenced credential files, and require fresh credentials. C23 handles the comprehensive import/recovery workflow.

## Required acceptance

- Production credential-entry/profile-import React suites verify transient entered input is cleared after submission, excluded from snapshots/observations and captured faithfully for preview; do not claim JavaScript strings can be reliably zeroized.

- desktop-host ipc_admission/keychain_access targets exercise actual host validation and OS adapter lock/ACL failure paths. System proxy mode builds a fresh client per dispatch admission, with changed-settings fixtures and no observer assumption.

- Delivery sequence eviction/gaps/max rotation/reload cannot replay work or permanently exhaust a context. Classic login Keychain ACL/locked/denied fixtures and direct/system/explicit proxy plus OS trust/root-policy races are natively qualified.

- Any changed UI also requires T09 actual native keyboard/focus/accessibility checks; global requirements are not deferred solely to C24.

- T01,T05–T07: switch/replace/sign-out during work, duplicate reply, expired/locked/denied vault, restart and session-only cleanup.
- Malicious IPC arguments, wrong origin/redirect, inherited env files and ambient credential fallback rejected.
- SDK source tests and desktop adapter tests execute natively with independent fixture transport; no live endpoints.
- T05,T09,T18: approved custom endpoints work, wrong-origin redirect/rebinding is denied, and explicit metadata import previews all changes without reading referenced credentials, retaining secrets, or changing the source. A rejected import leaves the current tenant unchanged.

G01/C01 must bind these assertions to exact commands and fixture/native targets
before execution. Run appropriate regressions when changes reach earlier chunks.
