# C07 offline acceptance matrix

Each C07 requirement, where the desktop proves it, and what it leaves to
Academy. Rust: `crates/desktop-core/tests/academy_offline` (production
authority interface, synthetic Academy over TLS; "unreachable" closes every
request, token renewal included) and the store's unit tests
(`crates/desktop-core/src/offline.rs`). React:
`apps/desktop/src/features/academy/offline-work.test.tsx`,
`host-actions.test.ts`, `src/contracts/snapshot-validation.test.ts`.
Academy: the pinned `use-desktop-draft` suite ("desktop lab work kept on the
device"). Native: `docs/planning/evidence/C07/native-acceptance.json`
(C07-N01..N10) against the synthetic endpoint
(`tools/native-acceptance/academy_offline.py`).

| Requirement | Desktop behavior | Rust | React / Academy | Native |
|---|---|---|---|---|
| Account-scoped sealed storage | Per-account directory (digest name) and key (learner Keychain, created on first use); XChaCha20-Poly1305 records bound to account and file name; 0700/0600; nothing readable on disk | `a_downloaded_course_is_kept_sealed_for_its_account_under_academys_lease`; store: `records_are_sealed_and_never_on_disk_in_plaintext` (with 0700/0600), `another_account_or_key_cannot_read_it_and_unreadable_records_are_kept`, `a_record_moved_to_another_name_does_not_authenticate`, `one_instance_holds_an_account_and_keys_must_be_32_bytes` | — | N01, N02 |

| Offline drafting, explicit submission | The latest unconfirmed lab work kept on this Mac (after each edit, a failed save and leaving the lab, in one ordered queue) and restored as "saved on this device only"; never sent by itself; the learner's save sends it on its base version (a moved-on copy is Academy's conflict); forgotten once Academy holds the latest work, a failed clear asked again | `lab_work_kept_on_this_mac_survives_restart_and_is_never_sent_by_itself` | `lab work kept on this Mac` (host-actions, 3); Academy `desktop lab work kept on the device` (6: latest edit after leaving with an older request pending, late device read after confirmation, failed clear) | N04, N05 |

| Locking and isolation | Sign-out, account change or a new generation locks offline work; another account never opens the first's directory or key | `sign_out_locks_offline_work_and_another_account_cannot_see_it`, `only_the_signed_in_current_learner_keeps_work_offline` | `is not offered to guests…`; snapshot: offline work shown while signed out is a contract violation | N06 |
| Vault denial and corruption | A denied Keychain keeps offline work closed and writes nothing; a corrupt record is kept aside | `a_denied_keychain_keeps_offline_work_closed_and_writes_nothing`, `an_unreadable_record_is_kept_aside_and_the_rest_still_opens` | `is not offered to guests, and offline storage that could not open says so` | — (fixture keychain not made to refuse) |

| T09 native UI | Download by keyboard, offline notice, zoom and minimum size | — | — | N01, N03, N09 |
| T11 authority | Offline procedures carry the account credential and stay within the allowlist; ids that name records are plain and bounded | `only_the_signed_in_current_learner_keeps_work_offline` | snapshot validation (ids, instants, statuses) | N10 |
